## 1. Цель и задачи работы

**Цель работы:** освоить практический процесс публикации статического веб-ресурса в публичном облаке Amazon Web Services (AWS) с выстраиванием автоматизированного конвейера непрерывной интеграции и доставки (CI/CD) на базе GitHub и AWS Amplify, а также провести анализ рисков информационной безопасности развернутой облачной инфраструктуры.

**Выполненные задачи:**
1. Разработан одностраничный сайт технологического медиа-проекта **x1nets** (`index.html`, `style.css`) на базе семантического HTML5 и современного CSS3 без внешних runtime-зависимостей.
2. Инициализирован репозиторий на GitHub и загружены исходные файлы проекта.
3. Настроена интеграция репозитория с облачным сервисом **AWS Amplify Hosting** по модели GitOps / Continuous Deployment.
4. Выполнена публикация проекта с автоматическим выпуском SSL/TLS-сертификата и раздачей через глобальную сеть доставки контента AWS CloudFront CDN.
5. Проведена оценка киберрисков (CyberRisk Assessment) используемой архитектуры хостинга.

## 4. Анализ киберрисков облачного хостинга (CyberRisk Assessment)

| Киберриск / Вектор угрозы | Уровень риска | Возможные последствия | Реализованные и рекомендуемые меры защиты (Mitigation) |
| :--- | :--- | :--- | :--- |
| **Компрометация цепочки поставок (Supply Chain / CI/CD Attack)** | Средний | Несанкционированный коммит в ветку `main` на GitHub с автоматической выкаткой вредоносного кода на продакшн-сервер AWS. | Использование двухфакторной аутентификации (2FA) в GitHub и AWS; настройка правил защиты ветки (`Branch Protection Rules`). |
| **Утечка чувствительных данных в публичном репозитории** | Низкий | Публикация ключей доступа, токенов или внутренних конфигураций в истории Git. | Исключение секретов из клиентского кода; хранение переменных окружения строго в защищенном хранилище AWS Amplify. |
| **DDoS-атаки прикладного уровня (L7 HTTP Flood)** | Средний | Отказ в обслуживании или исчерпание лимитов трафика облачного аккаунта. | Кэширование статики на узлах CDN CloudFront, базовая защита AWS Shield Standard и возможность подключения AWS WAF (`Enable firewall`). |
| **Перехват трафика (Man-in-the-Middle)** | Низкий | Перехват или модификация трафика между браузером пользователя и сервером. | Принудительное использование HTTPS (TLS 1.2/1.3) с управляемым сертификатом от Amazon Certificate Manager. |
| **Отсутствие строгих HTTP-заголовков безопасности** | Низкий | Потенциальные векторы Clickjacking или MIME-sniffing на стороне клиента. | Настройка кастомных заголовков ответа (`Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`) в конфигурации Amplify. |

## 5. Вывод

В результате работы веб-сайт проекта **x1nets** успешно развернут в облачной инфраструктуре Amazon Web Services с использованием непрерывного развертывания (CI/CD) из репозитория GitHub. Выбранная бессерверная архитектура минимизирует поверхность атаки (отсутствуют уязвимости серверных ОС, СУБД и открытых портов управления), обеспечивает высокую скорость загрузки через CDN и защищенное соединение по протоколу HTTPS.
